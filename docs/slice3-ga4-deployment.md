# Slice 3 GA4 deployment and acceptance gate

Status: source implemented locally; **not deployed or E2E-verified** until the operator configures a Google OAuth client and a real Rocket app owner completes domain verification. Do not publish the frontend ahead of its migration and Edge Function.

## Operator configuration (no secret values in chat or Git)

1. In Google Cloud, use a project controlled by Rocket. Enable **Google Analytics Admin API** and **Google Analytics Data API**. Configure the OAuth consent screen for the read-only `https://www.googleapis.com/auth/analytics.readonly` scope. Add the real test founder as a Google OAuth test user if the app remains in testing mode.
2. Create a **Web application** OAuth client. Register this exact authorized redirect URI: `https://lcujmvdgczkjxdstzhnr.supabase.co/functions/v1/rocket-ga4`. The authorized JavaScript origin is not needed for this server-side flow. Google must be able to redirect to the Edge Function over HTTPS.
3. Set these Supabase Edge Function secrets directly in Supabase: `GOOGLE_GA4_CLIENT_ID` (web OAuth client ID), `GOOGLE_GA4_CLIENT_SECRET` (web OAuth client secret), `GA4_TOKEN_ENCRYPTION_KEY` (independent 32 random bytes encoded as base64/base64url), and `GA4_SYNC_SECRET` (independent high-entropy secret of at least 32 characters). Optional `GA4_FRONTEND_ORIGIN` defaults to `https://tryrocket.ai` and must be that exact origin in production. Do not reuse Rocket Connect or Stripe secrets.
4. Add GitHub Actions repository secret `ROCKET_GA4_SYNC_SECRET` with the **same value** as Supabase `GA4_SYNC_SECRET`. The workflow calls the service-only daily sync endpoint. Never commit or print either value.
5. Apply `20260929040609_slice3_ga4_verified_traffic.sql`, deploy `rocket-ga4` with JWT gateway verification disabled (the function verifies user JWTs itself for all owner actions and uses the separate high-entropy secret only for scheduled sync), then publish the frontend and enable the GitHub workflow. Review production logs for errors without logging provider credentials.

The Google redirect uses an authorization code, a 10-minute one-use server-stored state, PKCE S256, and an exact fixed callback. Only encrypted refresh tokens are persisted in private service-only tables. The function filters GA4 reports to the selected web stream's exact hostname; the stream's hostname must match the Rocket app's canonical verified domain. The initial query backfills 90 completed property-local days, then daily sync re-reads the most recent three completed days to absorb GA processing lag. Repeated writes upsert on connection/metric/date. The public profile reads only a redacted table subject to consent and a 72-hour freshness RLS limit. Ownership transfer/revocation removes credentials and public projection in the same database transaction.

The live proof requires an **actual `app_owners` record with `verification_level=domain_verified`**, for a real domain/GA4 web stream controlled by the founder. Do not insert this record manually. The founder must complete Rocket's production DNS or HTTPS claim flow. This is also the first manual production test of Slice 2's domain-verification mechanism, previously deferred by the operator.

Acceptance sequence: verify owner can start OAuth; non-owner cannot; Google consent returns to property selection; reject unrelated property/stream; verify matching stream and real backfill; check all visibility PRIVATE; publish one metric by explicit owner choice; inspect anonymous public projection; verify another user cannot query raw tables or credentials; run daily sync twice and confirm no duplicate point keys; disconnect and confirm public evidence disappears while historical private points remain; test owner transfer/revocation invalidation. No traffic badge should be called verified before this sequence passes.

Rollback: disable the GA4 frontend route/link and scheduled workflow, and disable/delete the `rocket-ga4` deployment. Keep the private point tables intact for forensic/recovery purposes; do not drop the migration or erase unrelated app data. Public projection can be cleared for affected apps if the feature is withdrawn.

Source documentation: [Google web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Analytics Admin account summaries](https://developers.google.com/analytics/devguides/config/admin/v1/rest/v1beta/accountSummaries/list), [GA4 web streams](https://developers.google.com/analytics/devguides/config/admin/v1/rest/v1alpha/properties.dataStreams), [GA Data API reporting](https://developers.google.com/analytics/devguides/reporting/data/v1/basics), [GA4 metric and hostname definitions](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema).
